# Спортивный аналитик

Telegram-бот для анализа спортивных событий, статистики, вероятностей исходов,
коэффициентов и поиска вилок. Реализация построена по спецификации из
`Паспорт_бота_Спортивный_аналитик_MVP.docx`.

## Статус

Рабочее ядро MVP: все 12 пользовательских функций и 10 функций владельца из
паспорта имеют реализацию или явно помеченную заготовку (см. таблицу ниже).
Внешние платные источники данных (Sportradar, API-Football, Sofascore, реальные
STT/LLM-провайдеры, платежи) не подключены — ключей/договоров для них нет, поэтому
их место занимают мок-адаптеры с демо-данными на 6 видов спорта MVP (футбол,
теннис, баскетбол, хоккей, бокс, MMA). Архитектура специально построена так, чтобы
замена мока на реальный источник не требовала правок в обработчиках — расписание
боксёрских боёв уже так подключено к Boxing Data API, см. «Реальные данные: бокс»
ниже.

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впишите BOT_TOKEN от @BotFather и, по желанию, ADMIN_IDS
python -m bot.main
```

`ADMIN_IDS` — через запятую Telegram ID владельцев, которым доступна команда
`/admin`. База данных — SQLite (`bot.db`), создаётся автоматически при первом
запуске.

## Архитектура

```
bot/
  config.py          — настройки из .env (pydantic-settings)
  constants.py        — 6 видов спорта MVP
  filters.py           — фильтр IsAdmin
  db/                  — SQLAlchemy: пользователи, лог запросов, вкл/выкл спорта, подписки
  services/
    adapters/base.py    — интерфейсы источников данных (сюда встраиваются реальные API)
    adapters/mock_*.py  — демо-реализации этих интерфейсов
    registry.py          — единая точка переключения мок → реальный адаптер
    analytics.py          — расчёт вероятностей и поиск вилок (отдельно от LLM/AI)
  keyboards/            — инлайн-клавиатуры
  handlers/              — обработчики команд/колбэков, по одному файлу на функцию
  handlers/admin/         — функции владельца, доступны только ADMIN_IDS
  middlewares/access.py    — блокировка доступа заблокированным пользователям
  main.py                   — точка входа, регистрация роутеров, polling
docs/
  index.html                 — статичная страница Mini App
  style.css                    — тема, подстраивается под Telegram (свет/тёмная)
  data.js                       — те же демо-данные и формулы, что в bot/services
  app.js                          — навигация и рендер экранов
```

Принцип из паспорта соблюдён буквально: «внешние источники подключаются через
отдельные адаптеры и приводятся к единому внутреннему формату» — см.
`bot/services/adapters/base.py`.

## Свободные вопросы через DeepSeek

По умолчанию функция 7 (свободные вопросы) отвечает заглушкой. Чтобы
подключить настоящую LLM (DeepSeek):

1. Получи API-ключ на `platform.deepseek.com` (раздел API Keys).
2. Впиши его в `.env`: `DEEPSEEK_API_KEY=твой_ключ`.
3. Перезапусти бота — `bot/services/registry.py` сам переключится на
   `DeepSeekNLUAdapter` (`bot/services/adapters/deepseek_nlu.py`), как
   только ключ не пустой.

Код общается в формате OpenAI (`/chat/completions`), поэтому вместо DeepSeek
можно подключить любого совместимого провайдера (OpenRouter, Groq, Together,
локальную модель) — не трогая код: положи его ключ в `DEEPSEEK_API_KEY`, а
адрес и название модели в `LLM_BASE_URL` и `LLM_MODEL`. Пустые — значит
DeepSeek по умолчанию.

LLM отвечает только на текстовые вопросы не по числам — конкретные
коэффициенты и вероятности она вообще не считает и не называет (это
принципиально: паспорт бота требует, чтобы расчёт вероятностей никогда
не выполнялся исключительно LLM). Для них по-прежнему работают отдельные
команды меню (`services/analytics.py`, мок-коэффициенты).

## Telegram Mini App

`docs/` — рабочее веб-приложение (чистые HTML/CSS/JS, без сборки и
бэкенда): виды спорта → события → анализ/коэффициенты/вилка, статистика,
сравнение, новости. Данные и формулы продублированы из `bot/services/`
один в один (проверено сравнением с реальным выводом бота), поэтому цифры
в приложении и в чате совпадают.

Чтобы кнопка «Меню» в боте открывала это приложение, нужен публичный
HTTPS-адрес (Telegram не открывает `http://` и localhost). Самый быстрый
способ — бесплатный GitHub Pages:

1. В репозитории на GitHub: **Settings → Pages → Source** выбери
   **Deploy from a branch**, ветку `main` и папку `/docs` (GitHub Pages
   при деплое из ветки даёт выбрать только `/ (root)` или `/docs` —
   поэтому приложение лежит именно в `docs/`), сохрани.
2. Через 1-2 минуты GitHub выдаст ссылку вида
   `https://<ваш-логин>.github.io/turbo-fishstick/`.
3. Впиши эту ссылку в `.env` в строку `MINI_APP_URL=`.
4. Перезапусти бота (`Ctrl+C`, затем снова `python -m bot.main`) — при
   старте он сам вызывает `setChatMenuButton` и подставляет кнопку
   «Открыть» вместо стандартного меню команд.
5. (Необязательно) Зарегистрируй то же приложение у @BotFather —
   `/newapp` → выбери бота → укажи тот же URL — тогда его можно будет
   также открыть через `t.me/<бот>/app` и делиться прямой ссылкой.

## Реальные данные: бокс (Boxing Data API)

Единственный реально подключаемый источник среди 6 видов спорта MVP —
Boxing Data API на RapidAPI (`rapidapi.com/bengroves1993/api/boxing-data-api`).
У него нет коэффициентов и нет MMA — только расписание/результаты боёв и
рейтинги бокса, поэтому реальными становятся только предматчевые события
бокса (и в чате бота, и в Mini App); коэффициенты и вилка для реальных
боёв показывают «недоступны» вместо выдуманных цифр — считать их не по
чему, у реальных боксёров нет рейтинга силы, который есть у демо-данных.

1. На `rapidapi.com` найди Boxing Data API и нажми **Subscribe** на
   тарифе Basic (бесплатный) — без подписки ключ вернёт 403, даже если
   сам ключ рабочий (это RapidAPI, а не ошибка ключа).
2. Впиши ключ в `.env`: `BOXING_DATA_API_KEY=твой_ключ`. Бесплатный тариф
   отдаёт расписание только на небольшое окно вперёд (на практике — около
   недели; более дальний запрос RapidAPI отклоняет с HTTP 403 "date out of
   range", а не потому что ключ неверный) — это ограничение самого
   тарифа, не кода; `BoxingDataApiAdapter` по умолчанию просит 5 дней
   вперёд, чтобы оставаться внутри лимита с запасом.
3. Перезапусти бота — `bot/services/registry.py` подключит
   `BoxingDataApiAdapter` (`bot/services/adapters/boxing_data_api.py`)
   только для `sport="boxing"`; остальные 5 видов спорта не меняются.

**Если стоит VPN/системный прокси (V2Ray, Clash и т.п.):** браузер и
PowerShell используют его автоматически через настройки Windows, а вот
Python (aiohttp — на нём построены и aiogram, и `BoxingDataApiAdapter`) —
нет, и идёт в интернет напрямую. Из-за этого возможны два разных отказа:
таймаут при подключении к `api.telegram.org` (сам бот не стартует) и/или
HTTP 451 от RapidAPI («Unavailable For Legal Reasons» — эмбарго/блокировка
по региону вашего настоящего IP, хотя тот же адрес прекрасно открывается
в браузере через прокси). Впиши адрес своего прокси в `.env`:
`PROXY_URL=http://127.0.0.1:10809` (порт зависит от твоего VPN-клиента —
посмотри в его настройках) — `bot/main.py` подключит его и для Telegram,
и для Boxing Data API.

Тот же бот-процесс поднимает маленький HTTP API (`bot/web/api.py`,
порт из `MINI_APP_API_PORT`, по умолчанию 8080) — `GET /api/events?sport=boxing`
отдаёт тот же список, что видит чат. Это нужно, чтобы Mini App (`docs/`,
статика на GitHub Pages) тоже показывал реальные бои: GitHub Pages не
может хранить серверный ключ, поэтому ключ остаётся на бэкенде, а
страница у зрителя лишь спрашивает у него расписание.

Чтобы Mini App реально это увидел:

1. Хостинг бота должен быть доступен по **публичному HTTPS** (не
   `localhost`) — так же, как для `MINI_APP_URL` выше.
2. В `docs/index.html` пропиши `window.MINI_APP_API_BASE = "https://..."`
   на этот адрес. Пустая строка (по умолчанию) — значит «источника нет»,
   и приложение продолжает работать на демо-данных, как раньше.
3. Хостинг должен пускать исходящие HTTPS-запросы на
   `boxing-data-api.p.rapidapi.com` — если бот работает за файрволом или
   в среде с ограниченным исходящим доступом (белым списком хостов), этот
   домен нужно явно разрешить, иначе `BoxingDataApiAdapter` будет получать
   403/таймаут и молча падать обратно на пусто (бот при этом не падает).

## Игра (казино) через нативную карточку Telegram

Помимо кнопки «🎰 Казино» внутри Mini App, игру можно запустить и через
классический Telegram Games API: команда `/game` в чате с ботом
(`bot/handlers/game.py`) отправляет нативную карточку «🎮 Играть в
Buntar analitic», по нажатию открывается тот же экран казино
(`docs/`, маршрут `?view=casino`).

Короткое имя игры (`GAME_SHORT_NAME = "casino_chronofag"` в
`bot/handlers/game.py`) должно совпадать с тем, что зарегистрировано в
@BotFather через `/newgame`. Таблица рекордов (`setGameScore` /
`getGameHighScores`) не подключена — она требует сервера с доступом к
токену бота, который мог бы принимать очки прямо со страницы игры;
здесь такого сервера нет, поэтому только запуск, без общего рейтинга
игроков.

## Ограничения (как в паспорте)

Вероятности и вилки — модельная оценка на демо-данных, не гарантия результата и
не финансовая рекомендация. Для продакшена необходимо подключить лицензированные
источники (Sportradar, API-Football и т.д.) и заменить мок-адаптеры реальными
реализациями тех же интерфейсов.
