# Сравнить коэффициенты через четыре дня

Пользователь попросил 06.09.2026 сохранить текущую линию и сравнить её после своего напоминания. Автоматическое напоминание и фоновое задание не созданы.

## Исходный снимок

`baseline-2026-09-06.json` — точная копия серверного кэша до изменения интервала: 50 событий MMA и 41 событие бокса. Получено 06.09.2026 около 13:25 МСК. Внутри сохранены все букмекеры, рынки h2h/totals, коэффициенты и времена обновления, без API-ключа. Поле refresh_hours внутри снимка историческое, не текущая настройка.

Текущий интервал запросов линии: 96 часов. Следующая загрузка возможна после 10.09.2026 около 13:25 МСК, при открытом приложении либо новом запросе. Когда экран закрыт у всех пользователей, обновление само по таймеру не запускается. Отсчёт ведётся от fetched_at, а не от момента сохранения файла.

## Действия после напоминания

1. Не перезаписывать исходный снимок. Получить новый ответ Odds API через сервер после истечения кэша и сохранить новым файлом с датой.
2. Убедиться, что ответ не stale, fetched_at новый и last_update букмекера действительно изменился. Если данные те же, сообщить об этом, не выдавать сравнение кэша с собой за результат.
3. Сравнивать по id боя, ключу букмекера, рынку и имени исхода; для тоталов также по point. Не сравнивать котировки разных БК или разные пороги раундов как изменение цены.
4. Подготовить отдельную HTML-таблицу: бой (русское и исходное имя), БК, рынок/исход/порог, было, стало, разница, время линии до/после. Отдельно пометить новые и исчезнувшие события/котировки. Исчезновение не означает автоматически отмену боя.
5. Добавить краткую сводку: сколько выросло, снизилось, осталось без изменения; что не удалось сопоставить. Ссылку на HTML показать пользователю. PDF только если попросит.

Четырёхдневный снимок не является live-линией. Обновление метаданных BKFC раз в сутки — отдельная настройка, не расходующая кредиты Odds API.
