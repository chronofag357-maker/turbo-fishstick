# Видеокомната P2P Market — 08.09.2026

## Решение владельца

Свой интерфейс на LiveKit, не встроенная страница Jitsi.
Три видеоплитки, микрофон и текстовый чат. Без записи.
В прематче/купонах голос продолжается, камера приостанавливается.
При возвращении камера восстанавливается только если пользователь ранее
её включил. Явное отключение камеры/микрофона сохраняется.

Соединение и audio-элементы принадлежат главному документу Mini App,
а не удаляемому iframe трансляций. Вне комнаты компактная голосовая
панель: состояние связи, микрофон, возврат, завершение звонка.
Завершение звонка и выход из аккаунта освобождают все media tracks.
Скрытие Telegram может прерывать связь; это не обещание фонового звонка.

## Начатая реализация

POST /api/private/stream/token использует существующую серверную сессию
и проверку блокировки. Отдельный список LIVEKIT_PARTICIPANT_IDS ограничен
тремя аккаунтами; клиент не выбирает identity или комнату.
Ключ сервера не отдаётся браузеру. JWT действует 5 минут для входа,
но истечение JWT не отключает уже подключённого участника.
Отзыв доступа действующего участника потребует RemoveParticipant.
LIVEKIT_ENABLED по умолчанию false. LiveKit 1.13.6 запущен отдельной
службой p2p-livekit на VPS. Конфигурация /etc/p2p-livekit.yaml;
секреты для будущего backend /etc/p2p-livekit.env (600, root).
Бот пока не читает этот файл; новые frontend/backend ещё не выложены.

## Проверка VPS

1 vCPU, 1967 MiB RAM, доступно около 1408 MiB, диск 12 GiB свободен.
Оценка достаточности для 3 камер — только гипотеза до нагрузочного теста.
Начальный профиль: 360p/15 fps; без записи, транскодирования и egress.
HTTPS 443 занят Nginx, бот 8082. Нельзя занять/заменить эти порты.

## Реализовано и проверено 08.09

Собственные плитки docs/partner-room.js, CSS в палитре проекта,
SDK 2.22.3 поставляется локально с лицензией. Глобальный dialog и audio
не удаляются вместе с экраном трансляций. Голосовая панель вне комнаты,
камера приостановлена; сохранено явное выключение камеры пользователем.
Чат хранится только в памяти (до 100 сообщений), без истории сервера.

VPS: wss://159-194-244-46.sslip.io:8443 через отдельный Nginx server.
WebRTC 7881/TCP, 7882/UDP; встроенный TURN 443/UDP.
UFW открыт только на этих новых портах; 7880 снаружи закрыт.
Основной HTTPS и бот не менялись. Лимиты службы 700 MiB / 70% CPU.
TURN/TLS отсутствует: закрытые сети могут не подключаться.

Проверены 3 синтетических клиента через настоящий VPS: каждый получил
2 remote participant и 4 remote audio/video track, чат доставлен.
Это НЕ тест слышимости/камер на реальных телефонах.
Локальные mock-тесты 320/390 проверяют сохранение микрофона,
приостановку/возврат камеры и завершение звонка.

## Оставшаяся работа

1. Получить точные Telegram ID двух друзей, добавить только разрешённые ID.
2. Настроить отдельную службу, ограничения ресурсов, TLS reverse proxy
   для сигнализации и TURN для мобильных сетей. Проверить правила Beget.
   TURN/TLS 443 конфликтует с текущим HTTPS: нужен продуманный L4 proxy
   или отдельный адрес/узел; не выдавать TURN/UDP за полную замену TLS.
3. Подключить приватный env к backend при выкладке. max_participants=3
   уже задан на медиасервере, случайное имя находится в приватном env.
   Секреты только в закрытых env/config, не в Git и не в логах.
4. Проверить клиент после выкладки с реальной Telegram-авторизацией.
5. Проверить allowlist/выход/повторный вход, 3 устройства Wi-Fi+LTE,
   переход к боям с сохранением аудио, возврат видео и потерю сети.
6. Только после проверки заменить Jitsi. Старый рабочий интерфейс
   не удалять заранее; выкладка — по запросу владельца.
